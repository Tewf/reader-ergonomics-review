# Count every search

**Claim:** the protocol records every search string with its count, and says what was not searched, so that a reader can run the search again and compare.

- **Grade:** convention, by consensus: PRISMA 2020 item 7 and the 16 items of PRISMA-S ask for it. No study measured that a recorded search is reproduced more often.
- **Evidence:** [review, strand 1](../../evidence/review-genre/review.md); [Page 2021](../../evidence/bibliography.md), Table 1; [Rethlefsen 2021](../../evidence/bibliography.md); [Garousi 2019](../../evidence/bibliography.md), guideline 8.
- **Check:** `search-record` (exact): a table of strings, each with a count or the words not run, and no count shared by several strings. It warns when the protocol names no stopping rule or no gap in what it searched.
- **Reader styles:** none.

## What it asks

- One row per string, as run, with the source, the date and the count.
- State the stopping rule before the search, and apply it.
- Say what was not searched.

## Why

- A count lets a later reader see that a search returns what it returned.
- In one review, 30% of the sources came from the protocol's searches and 51% from snowballing (Greenhalgh 2005), so the record of strings is also a record of its own limit.

## Limits

- The check reads that a count is there, not that the engine returns it.
- Strings found by snowballing are recorded as a pass of their own, with the seed and the filter.
