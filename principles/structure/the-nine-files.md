# The nine files

**Claim:** a review keeps frame, protocol, sources, review, against, state of the art, position, baseline and references, one role each, so that a reader and a program find a result where it is kept.

- **Grade:** convention, untested. The contents are asked for by guidelines; the split into files is the family's.
- **Evidence:** [review, strand 1](../../evidence/review-genre/review.md); [baseline, B1](../../evidence/review-genre/baseline.md); [Page 2021](../../evidence/bibliography.md), Table 1; [Garousi 2019](../../evidence/bibliography.md), guidelines 1 to 14.
- **Check:** `review-files` (exact): each folder holds the eight files and a list of references, in the folder or once for the repository; whether a file holds what its shape asks is judgment.
- **Reader styles:** none.

## What it asks

- Keep each file to its role.
- Frame names the problem; protocol says how the pool was built; sources is the pool; review holds the findings.
- Against holds the evidence against; state of the art the records; position what is known and not; baseline the comparison.
- Keep references once: in the review's folder, or in the repository's one bibliography.
- Write each file to its [shape](../../shapes/README.md).

## Why

- PRISMA 2020 and Garousi 2019 ask for the contents (search, selection, flow, limits); a reader looks for each in the same place when the files are fixed.
- The files against, position and baseline are in no guideline: they are the family's.

## Limits

- No study of which files of a review help a reader was found.
- PRISMA items 24 to 27 (registration, support, competing interests, availability) have no file; the protocol and the front page carry them.
